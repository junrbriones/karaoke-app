# JBKaraoke

A karaoke/live-singing songbook: add lyrics with guitar chords, transpose on
the fly, and run a set through a distraction-free Stage Mode with a
tempo-driven word highlight. Built on Rails 8 + [Inertia Rails](https://inertia-rails.dev)
+ Vue 3 + TypeScript, from the [inertia-rails/vue-starter-kit](https://github.com/inertia-rails/vue-starter-kit)
boilerplate.

## Setup

```
bin/setup
```

This installs gems and npm packages, prepares the SQLite database, and
starts the dev server (Rails + Vite) at http://localhost:3000.

Then run the seed task to get a demo account with three public-domain
sample songs (Amazing Grace, Oh! Susanna, Auld Lang Syne):

```
bin/rails db:seed
```

Sign in with **demo@example.com** / **password12345** &mdash; it's seeded as
an admin. There's no public registration; see [Administration](#administration)
below for how an admin adds other people.

### A note on how this was built

This app was assembled by an AI agent working in a sandboxed environment
whose network policy allows npm's registry but blocks rubygems.org. That
means the Vue/TypeScript frontend has, on every feature added so far, been
fully installed, type-checked (`vue-tsc`, strict mode), linted (`eslint`),
formatted (`prettier`), and production-built (`vite build`) with zero
errors — all genuinely verified, including the `@rails/actioncable` client
added for Live Sync and the self-hosted `@fontsource/montserrat` font added
for the TV display (whose screens were also rendered in headless Chromium
at 1080p and 4K to check sizing, layout, and remote navigation). The Ruby side (models, migrations, controllers,
routes, channels, and hand-edited `db/schema.rb`) is written carefully
against the exact patterns already in this codebase and double-checked with
`ruby -c` for syntax, but the agent's sandbox can't run `bundle install` or
boot Rails, so none of it executes real ActiveRecord/ActionCable code until
you do. (One thing the agent *could* confirm by reading the SQLite file
directly: earlier rounds of `bin/rails db:migrate`, run by you outside this
sandbox, are already applied through the Setlists feature — so `bin/setup`
does work in your real environment. The `live_sessions` table (including
its `count_in_beats` column, added for the count-in cue) and the Action
Cable wiring are new since then and still need that same `bin/rails
db:migrate`.) If something's off on the Ruby side, that's the first place
to look.

One specific thing to know: `app/javascript/routes/SongsController.ts`,
`GroupsController.ts`, `UsersController.ts`, `MembershipsController.ts`,
`SongSharesController.ts`, `SetlistsController.ts`,
`SetlistSongsController.ts`, `LiveSessionsController.ts`,
`Admin/UsersController.ts`, `Admin/GroupsController.ts`, `index.ts`, and the
`setlistStage` entry in `RoutesController.ts` were hand-written to match this
app's [Typelizer](https://github.com/skryukov/typelizer)-generated
route-helper convention, not actually generated by it. Once gems are
installed, running Typelizer's generator will overwrite them with the real,
verified output (which should look the same, since `config/routes.rb` is
what it reads).

Administration also adds a migration (`add_admin_to_users`) on top of
everything the Setlists/Live Sync note above already flags &mdash; run
`bin/rails db:migrate` for that too.

Karaoke Sync (below) adds two more migrations on top of all of the above:
the standard Rails `active_storage` tables (for the uploaded audio files)
and a `phrasing` JSON column on `songs` &mdash; run `bin/rails db:migrate`
once more to pick those up too. It also adds one more hand-written route
file to the list just above, `app/javascript/routes/Songs/PhrasingsController.ts`
(exported as `songsPhrasings`), matching the same nested-singular-resource
pattern as `LiveSessionsController.ts`.

## The song format

A song's lyrics/chords live in one text field (`body`). A line made up only
of chords is automatically paired with the lyric line right below it, so
you can paste chord sheets copied from elsewhere. Put each chord over the
syllable where it changes; indenting the lyrics is fine.

```
[Verse 1]
     C         Em         F           Em
   Tayo ay magsaya at iwanan ang problema
```

- Wrap section names in brackets: `[Verse 1]`, `[Chorus]`, `[Bridge]`.
- Blank lines are kept as spacers.
- Chords can be anything a band would write: `Am`, `Bb`, `Cmaj7`, `Dm7`,
  `Cm7b5`, `G7sus`, `Gsus4`, `Fadd9`, `C7(b9)`, `C6/9`, slash chords like
  `D/F#`, and `N.C.`. Chords played within the same bar can be joined with
  dashes: `Dm-G7sus-G7` (a trailing dash is fine too). Bar lines (`|`),
  hold dashes (`Am - D7`), and similar markings are allowed in a chord
  line without breaking it.
- If a line is ever misread, force its type with a leading marker:
  `| G   D   C` forces a chord line, `> spoken intro` forces a lyric line.
  The editor also lists any line that looks like chords but was read as
  lyrics, naming the chord it didn't recognize.

**Instrumentals.** A chord line with nothing below it is instrumental
&mdash; an intro, interlude, solo, turnaround. Each chord, or each
dash-joined group, is one bar (the group's chords share the bar evenly), so
this intro is three bars:

```
[Intro]
   F Em Dm-G7sus-G7-
```

Add `x2` (or `2x`) at the end of the line to play the run that many times.
(This used to mean "make this line span N bars"; it now means "repeat it N
times", which is how chord sheets use it &mdash; drop it from any older
song where it was only there to stretch a line to one bar per chord.)

In Stage Mode and Live Sync the tempo guide plays an instrumental at that
pace, and the karaoke screen turns into a band chart for its length: one
box per bar with the current bar outlined and the chord being played lit,
a "Bar 2 of 3" counter, a beat light for each beat of the bar, a count-in
before the first chord when the song starts with one, and the 4-3-2-1
countdown to when the vocals come back in.

**Repeats.** Don't retype a section that comes back. A section header that
starts with `Repeat` plays an earlier section again:

```
[Repeat Refrain]
[Repeat Chorus 1]
[Repeat Interlude]
[Repeat Chorus 2 2x, fade]
```

The name matches an earlier section (`[Repeat Chorus]` picks the most
recent `Chorus ...`), `2x`/`x2`/`twice` sets how many times, and anything
after a comma is a note shown with the section (`fade`). `Rpt`, `Ulit`, and
`Ulitin` work in place of `Repeat`. Repeats are expanded when the song is
read, so the song page, Stage Mode, Live Sync, and the phrasing editor all
see the song as it's actually performed, with the repeated sections
labeled "(repeat)". The song editor has a **Repeat** bar that inserts one
for any section you've written, and it flags a repeat whose section it
can't find.

Title, artist, key, capo, and tempo are separate fields on the song, not
part of that text.


### Importing many songs at once

**Songs &rarr; Import** (`/songs/import`) brings in a whole batch of chord
sheets, from files and/or pasted text:

- **Files**: drop them on the page or choose them &mdash; plain text
  (`.txt`) with chords above the lyrics, ChordPro (`.cho`, `.chopro`,
  `.chordpro`, `.crd`, `.pro`), or a `.zip` of any of those (up to 1 MB a
  sheet, 25 MB a zip; anything else is listed as skipped). Files are read in
  the browser (UTF-8, or Windows-1252 from older editors).
- **Paste**: several songs in one box, with a line of `---` between them.
- **ChordPro** is converted: `{title}`, `{artist}`/`{subtitle}`, `{key}`,
  `{capo}` and `{tempo}` fill in the song's details; `{start_of_chorus}`,
  `{start_of_verse: Verse 2}`, `{comment: Interlude}` and the like become
  `[Chorus]`, `[Verse 2]`, `[Interlude]` headers; and each inline `[C]chord`
  goes on a chord line above its lyric, at the column where it was.
- **Plain text** keeps its chord lines as they are. `Title:`, `Artist:`,
  `Key:`, `Capo:`, `Tempo:`/`BPM:` lines at the top are read as details;
  otherwise the first line is the title (`Title - Artist` or `Title by
  Artist` splits off the artist), or the file name is (`Artist -
  Title.txt`). Section labels written as `Chorus:`, `VERSE 1` or `(Bridge)`
  become `[Chorus]`, `[Verse 1]`, `[Bridge]`.

Every song is listed to check before anything is saved: the title and
artist can be edited (&#8644; swaps them), **Preview** shows the sheet as
the app will display it next to its text (editable, with any lines worth a
second look flagged), and anything already in your songs &mdash; or in the
list twice &mdash; is pointed out and left unticked. **Import** saves the
ticked songs (up to 200 at a time) all together: if any can't be saved,
none are, and the reason shows against that song so it can be fixed or
unticked. Import only chord sheets you have the right to use.

## Guitar chord charts

**Chords** in the sidebar (`/chords`) is a chord dictionary for anyone
learning guitar. Type a chord name -- `C#m7`, `c#m7`, `Bbmaj7`, `B♭maj7`,
`G/B`, `F#7(b9)`, `Bø`, `E°7` -- and it shows:

- the chord's full name ("C sharp minor seventh"), its notes (C# E G# B,
  root in orange), its formula (`1 b3 (5) b7`; a note in brackets can be
  left out), and its other name when it has one (Dbm7);
- up to six ways to play it, the most common first and then others up the
  neck: a chart for each with the fingers to use (1 index to 4 little), the
  barre, × for strings not played and ○ for open strings, the note each
  string plays, and the shape in tab form (`x46454`).

Typing a kind of chord instead ("minor seventh", "diminished", "sus")
lists those chords; the row of note buttons and the grid below browse every
chord on a root (29 kinds: major, minor, 7, maj7, m7, sus2/sus4, 7sus4, 6,
m6, add9, m(add9), 9, maj9, m9, 6/9, dim, dim7, m7b5, aug, 7#5, 7b5, 7b9,
7#9, m(maj7), 11, m11, 13, 5). The address follows the search
(`/chords?q=C%23m7`), so a chord can be bookmarked or sent to someone.

Nothing is typed in by hand: `lib/guitarChords.ts` works out each chord's
notes from music theory and searches the fretboard (standard tuning) for
playable shapes, scoring them so the familiar open chords and E-/A-shape
barre chords come first -- so every chart is right for any root.

Each song's page also has a **Chord charts** panel (collapsible) with a
chart for every chord the song uses, in the order they first come up, and
in the key it's being shown in -- transpose the song and the charts follow.
Tap one for the other ways to play it.

## Administration

Only an admin can add a user or a group &mdash; there's no public sign-up,
and creating a group is otherwise gated the same way. An admin gets an
**Admin** entry in the sidebar, which opens `/admin/users`: a list of every
user, and a "+ New user" button (name, email, and a password the admin
sets and shares with them directly). They're sent an email to verify their
address &mdash; unless the admin ticks **Mark as verified**, vouching for
the address themselves: the account is verified from the start and no
email is sent. Creating a group works the same way,
gated onto the same `/admin/groups/new` form, and the "+ New group" button
on the Groups page only shows up for an admin.

There's deliberately no interface for granting the admin flag itself
&mdash; only someone with shell access can create the first admin or
promote another user, from `bin/rails console`:

```ruby
User.find_by(email: "someone@example.com").update!(admin: true)
```

The seeded demo account (`demo@example.com`) is admin by default, so a
fresh `bin/rails db:seed` always leaves you with at least one.

### Resetting a forgotten password

While the app has no email set up, a "Forgot password?" link can't send
anything -- so an admin sets a new password instead: **Admin → Users →
Reset password** next to their name.

- A random password is already filled in when the page opens. **Generate
  password** makes another: *Easy to share* (four groups of letters and
  numbers, `Kx7m-Pq2r-Tz9w-Hn4c`, easy to read out or type on a phone) or
  *Strong* (16 characters with symbols). They're made with the browser's
  cryptographic random numbers and leave out look-alike characters (0/O,
  1/l/I). You can also type your own (12 characters at least).
- **Ask them to choose their own password** (on by default): after they
  sign in with it they're taken straight to Settings → Password and can't
  use the rest of the app until they've picked one only they know. The
  users list shows a "temporary password" badge until then.
- Saving signs them out on every device, so the old password stops working
  at once. The page then shows the new password and a ready-to-send message
  (sign-in link, email, password) with copy buttons -- it isn't shown again
  after you leave the page.
- It's recorded in the activity log ("Set a new password for a user").

The same generator and "choose their own password" option are on the **New
user** form. The forgot-password page tells people to ask an admin if no
email arrives.

### Activity log

**Admin &rarr; Activity** (`/admin/activity`) is a log of who did what:

- **Sign-ins**: signing in, failed attempts (against the account when the
  email belongs to one &mdash; "wrong password" &mdash; or the email tried
  when it doesn't), signing out, and logging out another device.
- **Account**: password reset requests and resets, email verification,
  password/email/profile changes, deleting an account.
- **Admin**: adding a user, creating a group.
- **Songs**: adding, editing, deleting and starring songs, opening Stage
  Mode, saving a karaoke sync or line timing, uploading audio or a
  minus-one.
- **Groups & live**: sharing songs, editing/deleting groups, adding and
  removing members, setlists, starting and ending live sessions.

Each entry has the time, the person, what it was done to (a song's title,
a group's name, as it was then), the app's own confirmation message, the
device (from the browser's user agent: "Chrome on Windows", "Samsung TV")
and IP address, and whether it went through &mdash; a refused or invalid
attempt is kept and marked "didn't go through", with the reason. Filter by
person, kind, period (24 hours to all time), failed only, or search names,
songs and IPs; 50 at a time, newest first. The top shows sign-ins and
failed sign-ins in the last 24 hours (click the failed count to see them)
and how many people were active this week. **Users** shows each person's
last sign-in, any failed sign-ins today, and a link to their activity.

Page views and live-session play/pause/tempo commands aren't logged, to
keep it readable. Entries are kept for a year (`ActivityEvent::RETENTION`)
and older ones are removed automatically; when an account is deleted its
entries stay, under the name and email it had. Logging never gets in the
way: if an entry can't be written, the action still goes through. The log
is `activity_events` (`app/models/activity_event.rb`); what's recorded is
listed in `app/controllers/concerns/tracks_activity.rb`.

## Groups

A group is a shared songbook for a band. Only an admin can create a group
(see [Administration](#administration)); whoever creates it becomes its
owner, and can add existing users to it by email from the group page
&mdash; there's no invitation flow for people without an account yet.

- **Membership**: a user can belong to any number of groups, and a group
  can have any number of members. Only the group's owner can add or remove
  members, or delete the group itself; any non-owner member can leave on
  their own.
- **Sharing songs**: a song always belongs to the person who created it.
  From a song's page, its owner can check off any of their groups to share
  that song into it &mdash; a song can be shared into several groups at
  once, or none. Sharing doesn't move or copy the song; it just grants
  read access.
- **Access**: a shared song is read-only for everyone except its owner.
  Other group members can open it and run it in Stage Mode, but only the
  owner can edit, delete, retitle, or manage its sharing &mdash; the group
  page and the song page both hide those controls for anyone else.
- **The group dashboard**: each group's page lists every song shared into
  it (by any member) alongside the member list, so a band can see its
  whole shared songbook in one place.

### Setlists

Beyond the group dashboard's flat list of shared songs, a group's owner can
put together one or more **setlists**: named, ordered runs of songs for a
specific rehearsal or show. Open a group and click **Setlists**.

- Only the group owner can create, rename, delete a setlist, or add/remove/
  reorder its songs. Every member of the group can open a setlist and run
  it in Stage Mode &mdash; the running order, up/down reordering, and the
  add-a-song panel are hidden for anyone but the owner.
- A setlist can only draw from songs already shared into that group. This
  guarantees every song in a setlist is one every member can actually open;
  unsharing a song from the group automatically drops it from any of the
  group's setlists too.
- A song can appear in any number of setlists across any number of groups
  &mdash; adding it to one doesn't remove it from another.
- This is a separate feature from the personal &#9733; **Starred songs**
  quick list on the songs page: starring is a one-person, unordered, always-
  on shortlist for whoever's signed in, while a group setlist is named,
  ordered, shared with the whole band, and managed by the group's owner.

**Your own setlists (solo).** Every user also has their own setlists, for
performing solo: **Setlists** in the sidebar (`/setlists`). Create, rename
and delete them; add any song you can open &mdash; your own, and anything
shared with a group you're in (the add panel searches as you type) &mdash;
reorder with &#9650;/&#9660;, and **Start Stage Mode** to play them in order.
A song's page has an **Add to setlist&hellip;** picker (with "+ New
setlist&hellip;" to start one with that song). If a song is later unshared
from you, it stays listed, marked "no longer shared with you", and is
skipped in Stage Mode. The &#9733; star (now labelled Star/Starred) is still
the quick A-to-Z list, shown alongside your setlists.

### Live Sync

A song (or a whole setlist) can be played in sync across every group
member's own device &mdash; everyone's screen scrolls and highlights
together during a rehearsal or a show, without anyone needing to be in the
same room glued to one phone.

Live Sync uses the same TV screen and controls as Stage Mode (see
[Stage Mode](#stage-mode-the-tv--kiosk-display)).

- **Starting one**: from a group's page, pick a song and click **Start live
  session**; from a setlist's page, click **Go Live with the group** to run
  the whole running order. Any member who can see the song(s) can start a
  session &mdash; whoever starts it becomes that session's leader.
- **Leading vs. following**: the leader gets Play/Pause, Restart, Next/Prev
  (for a multi-song session), and Tempo -/+ in the control dock, and
  beats-per-line, count-in, and End session under **Settings**. A tempo
  change mid-song keeps everyone on the same word: the server rescales the
  shared clock in musical time (`LiveSession#set_tempo!`), and a burst of
  presses on a remote is sent as one change. Everyone
  else's app just follows &mdash; their word highlight, current song, and
  play/pause state track the leader's in real time. Only the leader (or the
  group owner, as a safety net if the leader's device drops off) can end the
  session; starting a new one automatically ends whatever was running
  before.
- **What's shared vs. personal**: the tempo-guide clock and which song is
  playing are shared. Transpose/key, text size, karaoke vs. chord-sheet
  view, and chords on/off stay personal to each device &mdash; handy since a capo'd guitarist and a
  singer often want different keys, and it means Live Sync only drives the
  same word-by-word highlight everyone already knows from Stage Mode's
  tempo guide, not a raw scroll position (which wouldn't line up across
  different text sizes anyway).
- **Count-in cue**: before each song starts (on first play, on Restart, and
  on every song change), everyone sees the same beat-synced countdown
  &mdash; a progress bar and a big 4-3-2-1 &mdash; a shared "get ready"
  cue, like a drummer's count-in, defaulting to 4 beats. The leader can
  change it under **Settings** (0 disables it). It's driven by the same shared clock
  as everything else: the count-in is just the clock running through its
  negative seconds before the song's own timeline starts at zero, so
  pausing or resuming mid-countdown works exactly like pausing mid-song.
- **How it works**: this uses Action Cable (Rails' WebSocket layer) &mdash;
  a `GroupLiveChannel` that only members of the group can subscribe to. The
  leader's controls go through the same Inertia request/redirect pattern as
  everything else in this app; the resulting state change is then broadcast
  over the socket so every other open Live page updates immediately, without
  a page reload. No extra services to run: development uses Action Cable's
  in-process `async` adapter (already the starter kit's default), and
  production uses `solid_cable` (already in the `Gemfile`), so there's no
  Redis to install either.

## Stage Mode (the TV / kiosk display)

Open a song and click **Stage Mode**, or star a few songs in the library
(setlist songs are ordered alphabetically) and click **Start Stage Mode**
to run through them in order. Stage Mode &mdash; and Live Sync, which uses
the same screen &mdash; is built to be read on a big TV (think 70" at
10&ndash;20 feet), driven by a remote, an air-mouse, a keyboard, or touch.

**What's on screen.** A pure black background (whatever the app's
light/dark setting) with at most two lines of lyrics, centered, in
Montserrat Black (self-hosted, so it works on an offline kiosk; Arial
Black is the fallback). Lyric size is set in container/viewport units
rather than pixels, so a 4K panel shows the same physical letter height as
a 1080p one: about 10% of the stage's height by default, which works out
to roughly 190pt (a ~2" capital letter) on a 70" TV, adjustable from 70%
to 140% with the **Text** control. Line height is 1.5. Underneath, in its
own dimmed zone, is a one-line **Next** preview of what's coming, and
above the lines a badge for the current section or duet part.

- Lyrics are solid white and sweep to neon cyan as they're sung, letter by
  letter rather than whole words flipping: the clock is read every
  animation frame (not just on the audio element's ~4-per-second
  `timeupdate`), and the sung color is revealed by a clip that grows
  continuously through each word or syllable.
- Duets: `[Male]`, `[Female]`, and `[All]` &mdash; as phrasing markers, or
  as `[Section]` headers in a chord sheet &mdash; change the sweep color to
  cyan, magenta, or lime respectively, so each singer can see at a glance
  whose line it is.
- Lines never wrap. One that's too wide for the screen is shrunk to fit
  (down to half size) instead of spilling onto a third line, and every
  zone on screen has a fixed size, so nothing ever jumps around as screens
  change or the controls show and hide.
- A screen comes up as soon as the previous one has been sung (up to 3
  seconds before its first word), so there's always time to read ahead.
- Countdowns: during an intro, a long instrumental break (3.5s or more),
  or the tempo guide's count-in, the screen shows a progress bar across the
  whole rest plus "Vocals in Ns", then a big 3-2-1 (with matching dots)
  right before vocals come back in. With the tempo guide the count lands on
  the beat (4-3-2-1 in 4/4); with an audio sync it counts seconds.
- **Chords** (tempo-guide songs) shows each chord in neon yellow above the
  word it changes on, transposed with the key. Instrumental lines show
  their chord run with the current chord lit.

**Controls.** A dock of large buttons (about 3 inches tall on a 70" TV)
sits at the bottom: Exit, Prev/Next song, Restart, Play/Pause, Key -/+,
Tempo -/+ (karaoke view, and the chord sheet view of a tempo-guide song)
or auto-scroll Speed -/+ (the sheet of an audio-synced song),
Text -/+, Sheet/Karaoke (switch views), Chords (karaoke view; Vocals for an audio-synced song) or Scroll
(auto-scroll on/off, sheet view), and Settings (beats per line, count-in,
flats vs. sharps, full screen). While a song plays the dock fades out after
4 seconds and the cursor hides; any mouse movement, touch, or button press
brings it back, and it stays up while paused. Its space is always reserved,
so the lyrics don't move when it appears.

With a TV remote or D-pad: while the dock is hidden, the first arrow or OK
press only wakes it and focuses Play (nothing fires blind); after that,
arrows move between buttons (wrapping around) and OK presses the focused
one. Focus is a thick yellow ring. Hardware media keys (play/pause,
next/previous track) work through the browser's Media Session API, and the
screen is kept awake while playing where the browser supports it.

**Changing the tempo mid-song.** Tempo -/+ works while the song is
playing, and you keep your place: the highlight stays on the same word and
just carries on faster or slower from there (the clock is rescaled in
musical time rather than seconds, so it doesn't jump ahead or back). With
the tempo guide it steps the BPM by 2 (40&ndash;240). For a song synced to
its uploaded audio, it changes the track's playback speed in 5% steps
(70%&ndash;130%) without changing its pitch, and the lyrics stay locked to
the audio. Each new song starts back at its own tempo.

**The chord sheet view** works like a teleprompter. There's a fixed
reading line about a third of the way down the screen (marked by a cyan
tick in the left margin), and the song moves past it:

- For a tempo-guide song, **Scroll** moves the sheet at the *song's* pace:
  each line arrives on the reading line exactly as it starts and glides on
  over exactly as long as it lasts (its [line timing](#line-timing)), the
  current line marked but no ball &mdash; a clean teleprompter. Its speed
  is the Tempo -/+, so speeding up or slowing down keeps every line in
  proportion. (Settings &rarr; "Scroll at song pace" off switches back to
  free scrolling at a fixed speed.)
- With free **Scroll** on (audio-synced songs, or song pace off),
  whichever line is crossing the reading line is marked as the current one &mdash; a highlighted band with a
  &#9654; pointer &mdash; while lines already passed fade back and lines
  still to come are slightly dimmed, so the singer never loses their place
  at any speed. Speed -/+ changes how fast it goes (0&ndash;30) while it's
  moving; slow speeds scroll smoothly instead of all rounding to the same
  rate. An audio-synced song can auto-scroll while its track plays.
- With the **tempo guide** playing, the line being sung is eased onto the
  reading line as the song goes (a smooth glide, not a jump), marked the
  same way. A ball bounces along the words: it lands on each word just as
  it starts and arcs over to the next one in time with the music &mdash;
  across to the next line too &mdash; staying in the gap between the chords
  and the lyrics. Each word fills with color left to right as it's sung,
  and the words already sung on that line stay lit. Live Sync's sheet view
  does the same, following the shared clock.

Keyboard shortcuts: `Space`/`P` play/pause, `R`/`Home` restart, `,`/`.`
slower/faster (the tempo, or the free scroll speed),
`N`/`Page Down` next song, `Page Up` previous song, `[`/`]` key down/up,
`-`/`+` text size, `K` or `V` karaoke/sheet view, `C` chords, `M` vocals
on/guide/off (audio-synced songs), `S` scroll on/off (sheet view), `F` full screen, `Esc` hide the controls.

**Key change.** For a tempo-guide song, Key -/+ transposes the chords (and
shows the new key, e.g. "A (+2)"). For a song with an audio sync, it
pitch-shifts the backing track itself, up to 6 semitones either way,
without changing its tempo &mdash; so the lyric timing stays in sync. This
runs in an AudioWorklet (`lib/pitchShift.ts`), which browsers only allow on
a secure origin: open the app over `https` (or on `localhost`) on the TV,
or the Key buttons are disabled for audio songs. Playback doesn't touch Web
Audio at all until the key actually moves off 0. The shifter is a simple
granular one, fine for a few semitones, and adds up to ~40ms of latency
while shifted.

**Tempo guide.** A song without an audio sync is paced by its BPM and a
"beats per line" setting (4 by default, i.e. one bar in 4/4 &mdash; lower
it for a waltz), after a count-in (4 beats by default, 0 to turn it off).
It's a heuristic &mdash; `beatsPerLine` beats per lyric line, split across
the line's words by word length &mdash; not a frame-accurate sync, but a
steady visual metronome to keep a singer on tempo. Its screens follow the
chord sheet's own structure: blank lines and `[Section]` headers are breath
breaks, lines pair up two to a screen, and a chords-only line is an
instrumental rest.

Display preferences (text size, karaoke vs. sheet view, chords on/off,
beats per line, count-in, scroll speed and pace) are remembered per device.

### Line timing

A flat "every line is one bar" can't keep up with a real song: some lines
are held for two bars, some rush by in half of one, and an intro may be
longer than its chords suggest. No scroll speed matches that, because the
pace changes line by line. **Line timing** (the button on a song you own,
or Stage Mode &rarr; Settings &rarr; Edit line timing) gives each line its
real length, so the highlight, the ball, the band's instrumental guidance
and the sheet's scrolling all move on to the next line exactly when the
singer does &mdash; in Stage Mode and in Live Sync.

- **Tap along**: press *Tap along from the top* (or *Tap from here* on any
  line), sing or play along after the 4-beat count-in, and press `Space`
  (or the big *Next line* button) the moment each next line begins. The
  highlight waits at the end of a line for your tap rather than running
  ahead, so you're never chasing it. `Backspace` undoes the last tap and
  backs up to that line; `Esc` stops.
- **By hand**: each line's length in beats, with -/+ (half a beat) or
  typed in quarter beats, and a reset back to the default. Lines without
  their own length use the default ("Untimed lines", the same beats-per-line
  setting Stage Mode uses).
- **Preview** plays the sheet exactly as the TV shows it (ball on or off),
  from the top or from any line (&#9654;), and follows any edit live.

Lengths are saved in beats, not seconds, so the Tempo control still speeds
the whole song up or slows it down evenly &mdash; saving also stores the
tempo you timed it at as the song's tempo. An instrumental line's length is
spread evenly over its bars. A repeated section (`[Repeat Chorus 1]`)
shares the timing of the original. Each line is matched by its section and
position *and* its words, so if you rewrite a line, its old timing is
dropped rather than applied to the wrong words (two plain sections with
the same name are told apart as `Verse`, `Verse~2`). The timing is stored
on the song as `line_timing` (`songs.line_timing`, JSON).

## Karaoke Sync (KaraFun-style phrasing)

The tempo guide above is a heuristic metronome. For a song where you want a
real, frame-accurate sync &mdash; lyrics that light up in step with an
actual recording, the way KaraFun and similar karaoke players do &mdash;
a song's owner can open **Karaoke sync** from the song page and build one.

**Phrasing rules.** The editor breaks lyrics into "screens" of at most two
lines each, since that's what stays readable from across a room at
karaoke-sized font. You write plain lyrics text and the editor chunks it
for you:

- A single line break makes the second line of the same screen.
- A blank line (a paragraph break) clears the screen and starts a new one.
- If a paragraph runs longer than two lines, it's auto-split into
  consecutive two-line screens &mdash; the two-line cap always holds, even
  if you didn't break it up yourself.
- A line with just `[Male]`, `[Female]`, or `[All]` labels every screen
  from there on, for duets &mdash; drop in a new one wherever the part
  changes.
- A line with just `[Instrumental]` marks a rest: no lyrics, just a "take a
  breath" beat with a progress bar, shown between two sung screens for
  exactly as long as the gap between them.
- A hyphenated word (`Gabi-gabi`, `taga-Frisco`) keeps its hyphen on
  screen, and each part is timed as its own word &mdash; tapped (in word
  mode) and highlighted separately.
- Split a long word with `|` (`a|ma|zing`) to break it into syllables, each
  tapped and highlighted independently, so the color sweep can move across
  the word instead of lighting it up all at once; the `|` isn't shown.

Click **Build screens** to turn the current text into a starting set of
screens (it defaults to the song's existing lyrics, pulled out of the
`body` you already wrote, chords stripped &mdash; chords-only lines become
an `[Instrumental]` marker automatically). Editing the text and rebuilding
later keeps any timestamps you'd already tapped, matched back up by
position.

**Tapping the sync.** Upload the song's actual audio (mp3/wav/ogg/m4a/aac/
flac, up to 30MB) in the box at the top &mdash; it uploads as soon as you
pick the file and is saved with the song, so it loads by itself every time
after that (the box shows the saved file's name, size and upload date;
**Replace audio…** swaps it, keeping your taps). Then pick how to sync
under **How to sync**. Taps are read from the real `currentTime` of the
`<audio>` element (not the throttled `timeupdate` event), so they land at
real millisecond precision.

**Saving.** **Save sync** (or `Ctrl+S` / `⌘S`) saves the lyrics with
their timing marks, the taps, and the tempo and snapping; it works at any
point, so a half-tapped draft is safe to leave and come back to. The save
bar shows "Unsaved changes" until you do, and leaving or reloading the page
with unsaved changes asks first.

*Tap each line* (the default, and the easier one): click **Start tapping**
and press `Space` (or the big pad) the moment each **line** starts.

- Tap at the start of each `[Instrumental]` break too, and once more where
  the last line ends. A line otherwise lasts until the next tap; to mark
  exactly where it ends (a line followed by a breath or a gap), keep the
  key held while it's sung and let go when it ends.
- **Tempo.** Lines nearly always start on a beat, so a steady beat fitted
  through the taps gives the song's tempo, found automatically from the
  first four taps on (using the song's tempo, if it has one, as a hint).
  Lines on bar lines fit several tempos about equally well, so the best
  few are offered as **Best matches** to pick from, with ½×/2× and a typed
  BPM for anything else; it tells you how closely your taps sit on the beat.
  Saving can also make it the song's tempo (used by the tempo guide and
  Line timing).
- **Word placement.** Each word is sung for as long as its syllables take
  at the **Syllable pace** &mdash; Normal is ½ beat a syllable (Fast ¼,
  Slow 1) &mdash; from the line's tap on, so a line ends when its words do
  and the rest of the time until the next line is a breath; the highlight
  waits there instead of dragging. A line sung faster than that pace is
  squeezed to fit, and a line whose tap you held is sung right up to where
  you let go. ("Fill the line" instead spreads each line's words over the
  whole time to the next tap, as before; it's also what's used until
  there's a tempo.) The words then snap to the nearest beat, ½ beat
  (default) or ¼ beat, so the sweep moves in time with the music. If a line has more
  words than grid slots it uses a finer grid, then no snapping. Snapping
  can be turned off (for a live recording that drifts).
- **Timing marks** in the lyrics fine-tune it, and never show on screen:
  `~` after a word or syllable holds it one syllable longer per `~`
  (`ma-hal~~ kita`); `/` is a pause of one syllable per `/`, and the
  highlight waits (`ikaw / at ako`, or `ikaw/`; at the start of a line,
  `// Oh` delays the first word after the line's tap); `^` makes a word
  quick, half as long per `^`, so the highlight moves on to the next word
  sooner (`Si^ Annie`; `Si^^` quicker still, `^^^` quickest) &mdash; with
  snapping on, a quick word may hand over between grid lines (a ¼ beat for
  `^` on a ½-beat grid, ⅛ for `^^`). Changes to words and marks
  apply as you type &mdash; the practice screen updates right away and
  every tap is kept. Adding or removing lines or screens waits for **Build
  screens** (taps are then matched up line by line from the top).
- The **Line taps** list shows every tap: &#9654; plays from just before a
  line, &minus;/+ moves a tap by 0.05 s, and **Re-tap** clears the taps
  from there on and backs up so you can redo just that stretch.
  `Backspace` undoes the last tap (and backs up a little); `Esc` stops.

Everything is worked out from the line taps, so changing the tempo, the
snapping or the marks re-places the words instantly, without re-tapping.

*Tap each word*, for exact control: `Space` as each word or syllable
starts. `←`/Backspace undoes the last tap, `→` skips a word without timing
it, `Esc` stops. Click any word in the **Tapped times** list to clear every
tap from that point on and rewind the audio to just before it. Switching
from line to word mode starts from the word times the line taps placed, so
you can line-sync the song and then re-tap only the words that need it
(switching back re-places them from the line taps).

**Who can edit it.** A song's karaoke sync (and its audio and minus-one
uploads) and its line timing are its owner's to make &mdash; unless the
owner ticks **Let group members edit its karaoke sync and line timing**
under "Share with your groups" on the song's page. Then anyone in a group
the song is shared with gets the Karaoke sync and Line timing buttons too
(and Stage Mode's "Finish karaoke sync"/"Edit line timing"): one shared
version, the latest save wins, every save in the activity log under who
made it. The lyrics and chords stay the owner's to edit.

A song is only "ready" for Stage Mode once every line (line mode) or every
word (word mode) is tapped. Until then Stage Mode follows the tempo guide
(and says so: "karaoke sync unfinished" in its status, with a note in
Settings); the editor's save bar counts what's left, and **Tap the rest**
jumps to the first untapped line and taps only the gaps. The sync is stored on the song as `phrasing`,
including how it was made (`sync`: mode, tempo, beat position, snapping).

The editor's practice screen is the actual Stage Mode renderer in a 16:9
box, so what you see while tapping is exactly what the singer will see on
the TV.

**In Stage Mode.** A song with both audio uploaded and a fully-tapped
phrasing plays from its real audio track instead of the tempo guide: Play
starts the track, the sweep follows your tapped timestamps, and Key -/+
pitch-shifts the track (see [Stage Mode](#stage-mode-the-tv--kiosk-display)).
The recording plays in the **Karaoke** view only. The **Sheet** view of an
audio-synced song is silent and follows the karaoke sync instead: the chord
sheet scrolls line by line, with the ball on each word, exactly as the song
was tapped out (`lib/syncedSheet.ts` matches the sync's lines to the
sheet's by their words, in order; chord-only lines and any line that
doesn't match share out the time around them). It starts at the sync's
tempo (found from the line taps) and Tempo -/+ moves it in 2 BPM steps
(50&ndash;150%) without losing your place; Play shows the ball, Scroll is
the clean song-paced teleprompter (always at the sync's pace for such a
song), and there's a count-in. In any song-paced sheet, each line reaches
the reading line a moment before it's sung &mdash; **Lines arrive early**
in Settings, 0.5 s by default (0&ndash;1.5 s) &mdash; so the singer is
already looking at it when it starts; the marked line and the ball still
change right on time. Switching
between Karaoke and Sheet mid-song carries on from the same spot &mdash; the
recording hands over to the sheet's silent clock and back, at the same
speed. A setlist mixes freely: each song uses its own
audio sync if it's ready and the tempo guide otherwise.

### Vocals: singing over the band

For a song with a finished audio sync (every line or word tapped), Stage
Mode's karaoke dock has a **Vocals** button (also in Settings, and `M` on a keyboard) that cycles:

- **On** &mdash; the original recording.
- **Guide** &mdash; the lead vocal turned well down (about &minus;10 dB),
  so the melody is still faintly there to follow.
- **Off** &mdash; the singer's voice only: the song's **minus-one** track
  if it has one, otherwise the lead vocal masked out of the original.

It can be changed mid-song without losing your place (switching to and
from a minus-one carries on from the same spot), works with Key and
Tempo, and is remembered per device.

**Masking** (`lib/vocalMask.ts`) is the classic karaoke "center cancel",
done live in the browser with Web Audio &mdash; no upload or processing
needed, and it works over plain http too. A studio mix puts the lead vocal
dead center (the same in both channels), so the vocal range (about
160 Hz&ndash;8 kHz) of the center is removed, while the center's bass and
kick, its cymbals and air, and everything panned to the sides are kept.
Measured on test tones: a centered 1 kHz voice drops ~60 dB, 300 Hz ~20 dB,
3 kHz ~35 dB; bass and cymbals pass unchanged; panned instruments lose
3&ndash;6 dB. Limits: it can't do anything with a **mono** recording (the
settings say so when the track turns out to be mono), wide stereo reverb on
the voice and backing vocals can leave a trace, centered instruments in the
vocal range are lowered with it, and the masked sound relies on stereo
playback (through a single mono speaker much of the band cancels out too).
At Vocals On the original goes straight through, untouched.

**A minus-one track** is cleaner: upload it per song under **Minus-one
track** on the Karaoke sync page (it's saved with the song like the main
audio, and can be replaced or removed; a file identical to the main audio
is refused, since it would still have the vocal). Minus-one files often start a
little earlier or later than the original, so it's lined up automatically
after uploading (`lib/alignTracks.ts` matches the drum and bass hits the two
share, to within ~15 ms) &mdash; or press **Auto-align** &mdash; and can be
nudged by 0.05 s by ear. **Listen to: Original / Vocals masked /
Minus-one** plays any of the three in the editor, with the lyrics on the
same clock, so you can check the alignment (and hear what Vocals Off will
sound like); tapping works with any of them. The offset is saved with the
sync as `instrumentalOffset`.

## When something goes wrong

Errors show a JBKaraoke page that says what happened in plain words and
always offers a way forward, instead of a bare status page:

- **Not found (404).** It says what's probably missing based on the
  address &mdash; "We couldn't find that song: it may have been deleted or
  renamed, or it hasn't been shared with you" &mdash; shows the address
  that was tried, and links to the nearest pages that still work (a missing
  setlist offers its group's Setlists, the group page, and All groups). An
  unknown address gets this page at that same address.
- **No access (403), bad or stale requests (400, 422), server errors (500)
  and the server being down or busy (502&ndash;504)** each get their own
  explanation. Server errors offer **Try again** and show an error
  reference to pass to an admin (it's the request ID in the server logs).
  When the server is restarting or busy, the page tries again by itself
  after 20 seconds.
- Every error page has **Go back** (when there's somewhere to go back to)
  and a way home: **My songs** when signed in, **Sign in** when not. The
  main button is focused, so a keyboard or TV remote is one press away.
- **A form that sat open too long** (its security token went stale after a
  sign-out or a deploy) no longer fails with an error: the page reloads
  with a note that the change wasn't saved, ready to try again.
- **Signing in after being sent to the sign-in page** returns you to the
  page you were trying to open, instead of the dashboard.
- **Losing the connection** shows a "You're offline" notice until it comes
  back. A page that couldn't load gets a **Try again** button, and a change
  that couldn't be sent says it wasn't saved, so nobody assumes it was.
- If the server answers with something that isn't from the app (a proxy's
  "Bad Gateway" page, say), production shows a short notice with **Try
  again** rather than a popup of raw HTML.

Development still shows Rails' detailed error pages; preview the friendly
ones at `/errors/404`, `/errors/500`, `/errors/503`, etc. The static pages
in `public/` (same look, no app code) are only the last resort, for when
the app can't render its own error page at all.

## What's from the starter kit, unmodified

Authentication (sign up/in, email verification, password reset), account
settings (profile/password/email/sessions/appearance), and the overall
sidebar layout all come straight from the boilerplate. The "Dashboard" nav
item was renamed to "Songs" (with a new "Groups" item added alongside it)
and now points at the song library; everything else in
`app/javascript/{layouts,components/ui}` and the auth-related
controllers/models are untouched. The pre-existing `Badge` and `Checkbox`
shadcn components are reused for role labels and the song-sharing panel.
